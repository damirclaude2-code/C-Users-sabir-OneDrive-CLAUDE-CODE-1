## Записи

### 2026-08-27 — Главная рабочая папка живёт на Рабочем столе (OneDrive), не в Downloads

- Контекст: нужно было единое "главное окно" для всей работы с Claude Code.
- Решение: перенести `CLAUDE-CODE-1` из `Downloads`/`Projects` на реальный
  OneDrive-путь Рабочего стола.
- Почему так: пользователю удобнее находить папку там, где он её ожидает
  видеть визуально — на Рабочем столе.
- Альтернативы: оставить в `Downloads\Projects`.
- Когда пересмотреть: если пользователь сменит компьютер или отключит
  синхронизацию OneDrive.

### 2026-08-30 — Ежедневный архив результатов в отдельной папке по датам

- Контекст: пользователь хотел иметь резервную копию всех финальных
  результатов работы "на всякий случай", с возможностью искать по дню.
- Решение: `Cloud Code работа\ДД.ММ.ГГГГ\` — при первой задаче за день
  создаётся подпапка с датой, туда автоматически копируется каждый
  финальный файл (без даты в имени — дата уже в папке).
- Почему так: сначала пробовали дату в имени файла в одной плоской папке —
  оказалось хуже читается и сложнее ориентироваться, чем подпапки по дням.
- Альтернативы: дата в имени файла; отдельная папка на каждую задачу без
  привязки к дате.
- Когда пересмотреть: если архив станет слишком большим для ручного
  просмотра — рассмотреть автоматическую архивацию старых папок.

### 2026-08-30 — PPTX и PDF версии презентации собираются независимыми генераторами

- Контекст: одна и та же презентация должна существовать в двух форматах;
  риск, что баг верстки в одном формате перейдёт в другой при конвертации.
- Решение: `pptxgenjs` для PPTX и `pdfkit` для PDF — два полностью отдельных
  кодовых пути с одной и той же дизайн-системой, но независимой генерацией.
- Почему так: явное требование пользователя — "чтобы не плодить ошибки при
  создании презентации".
- Альтернативы: собрать один формат и экспортировать/конвертировать во
  второй через LibreOffice.
- Когда пересмотреть: если поддержка двух независимых генераторов станет
  слишком дорогой при дальнейших правках дизайна.

### 2026-08-30 — credentials.md сохраняет собственную структуру при новых установках

- Контекст: несколько установочных промптов (search-and-read-web и другие)
  предлагали свой шаблон `SERVICE_API_KEY=` для credentials-файла.
- Решение: не переписывать `credentials.md` под шаблон каждого нового
  промпта — сохранять существующую структуру
  (`### Сервис / Тип / Значение / Где используется / Дата / Комментарий`)
  и просто добавлять в неё новые записи.
- Почему так: явное правило самих установочных промптов — "не ломай
  существующую структуру".
- Альтернативы: переписывать под последний шаблон при каждой установке.
- Когда пересмотреть: не планируется — это принцип файла.

### 2026-08-30 — fact-checking skill осознанно не установлен

- Контекст: source-of-truth файл `06-fact-checking-skill-4-4.md` не был
  передан пользователем вместе с остальными файлами skill pack.
- Решение: не выдумывать содержимое навыка по аналогии с другими — честно
  пометить как отсутствующий в `CLAUDE.md` и в `skill-router`.
- Почему так: правило "не добавляй выдуманные факты" применимо и к
  содержимому самих skill-файлов, не только к обычным ответам.
- Альтернативы: написать `fact-checking` самостоятельно по образцу похожих
  навыков (`copywriter`, `designer`).
- Когда пересмотреть: как только пользователь пришлёт исходный файл.
