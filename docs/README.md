# Карта документации проекта

Этот файл — точка входа в документацию `CLAUDE-CODE-1`. Он отвечает на
вопрос "где что искать", а не хранит сами факты.

## Где что лежит

| Что нужно | Где искать |
|---|---|
| Правила работы с проектом (как я должен себя вести, режимы работы, безопасность файлов, credentials, автовыбор навыков, agentic triage) | [`CLAUDE.md`](../CLAUDE.md) в корне репозитория |
| Долговечная память проекта (кто пользователь, что за бизнес, словарь терминов, канонические ссылки) | [`project-memory.md`](project-memory.md) |
| Известные баги, gotchas и как их не повторить | [`bugs-and-gotchas.md`](bugs-and-gotchas.md) |
| Журнал долговечных решений и почему они приняты | [`decision-log.md`](decision-log.md) |
| Как работать с локальным Git (русский словарь команд) | [`local-git-workflow.md`](local-git-workflow.md) |
| Секреты и API-ключи | [`credentials.md`](../credentials.md) в корне (защищён `.gitignore`, не в этой папке нарочно — секреты живут отдельно от обычной документации) |
| Инструкции по запуску/деплою/проверке | Пока отдельного файла нет — проект не является кодовой базой с build/deploy шагами. Если появится код с командами запуска, добавить сюда `docs/runbook.md` |
| План LLM Gateway (SIMPLE — Gemini/Groq, COMPLEX — Claude/Codex CLI) | [`docs/llm-gateway/README.md`](llm-gateway/README.md) |

## Главное правило этой системы документации

**Один факт — одно каноническое место.** Если факт уже записан в
`project-memory.md`, `bugs-and-gotchas.md` или `decision-log.md` — не
копируй его в `CLAUDE.md` или в другой документ. Оставляй короткую ссылку
на канонический файл вместо повторения содержимого.

`CLAUDE.md` — короткий навигатор и вход в проект, а не хранилище фактов.
Детали живут в файлах этой папки.
