# Bugs and gotchas

Этот файл нужен, чтобы не наступать на одни и те же ошибки дважды.

## Как добавлять запись

Каждая запись должна отвечать на 5 вопросов:

1. Что сломалось?
2. Как это выглядело?
3. Почему это произошло?
4. Как исправили?
5. Как проверить, что больше не сломано?

## Записи

### 2026-08-27 — Папка создана не там, где пользователь видит Рабочий стол

- Симптом: созданная папка не появлялась на Рабочем столе пользователя.
- Причина: Рабочий стол синхронизирован через OneDrive и физически находится
  по пути `C:\Users\sabir\OneDrive\Рабочий стол`, а не по стандартному
  `C:\Users\sabir\Desktop`.
- Решение: перед созданием чего-либо "на Рабочем столе" уточнять реальный
  путь через PowerShell: `[Environment]::GetFolderPath("Desktop")`.
- Проверка: папка видна в Проводнике на реальном Рабочем столе пользователя.
- Где связано: `project-memory.md` → раздел "Контекст пользователя".

### 2026-08-30 — Кириллица в CSV ломалась при открытии в Excel

- Симптом: вместо кириллицы в Excel отображались "кракозябры".
- Причина: CSV был в UTF-8 без BOM-метки — Excel по умолчанию открывает
  такие файлы в системной (не UTF-8) кодировке.
- Решение: сохранять CSV с BOM-меткой (`EF BB BF` в начале файла) через
  `[System.IO.File]::WriteAllText(path, content, New-Object System.Text.UTF8Encoding $true)`.
- Проверка: открыть файл в Excel — кириллица читается без искажений.
- Где связано: `demo-3-2/summary-3-2.csv`.

### 2026-08-30 — Символ ⚠ не отображался в PDF/PPTX (пустой квадратик)

- Симптом: вместо предупреждающего треугольника ⚠ в сгенерированном
  PDF/PPTX рисовался пустой квадратик ("тофу", `.notdef`).
- Причина: шрифт Calibri, используемый для генерации, не содержит этот
  Unicode-глиф; pdfkit не делает автоматический font-fallback.
- Решение: не полагаться на Unicode-символы для иконок — рисовать значок
  вручную примитивами (треугольник + текст "!").
- Проверка: отрендерить PDF/PPTX в PNG и посмотреть глазами — иконка видна
  как обычная графика, не как квадратик.
- Где связано: генераторы `presentation-3-3.pdf`/`.pptx`.

### 2026-08-30 — git commit падал с "Author identity unknown"

- Симптом: `git commit` завершался ошибкой про неизвестную личность автора.
- Причина: в новом репозитории не была настроена `user.name`/`user.email`
  (ни локально, ни глобально).
- Решение: `git config user.name "..."` и `git config user.email "..."`
  локально для репозитория перед первым коммитом.
- Проверка: `git commit` проходит успешно.
- Где связано: первый коммит в `CLAUDE-CODE-1`.

### 2026-08-30 — Проводник Windows "не показывал" новые файлы

- Симптом: пользователь не видел новую папку `.claude/skills` в открытом
  окне Проводника, хотя файлы физически существовали на диске.
- Причина: не реальная скрытость файлов (атрибуты Hidden/System отсутствовали
  — проверено через `Get-Item -Force`), а кэш открытого окна Проводника,
  который не обновился после создания файлов внешним процессом.
- Решение: обновить окно (F5/Ctrl+R) или полностью закрыть и переоткрыть
  Проводник. Дополнительно можно проверить существование файлов в обход
  Explorer через `[System.IO.Directory]::GetFileSystemEntries(...)`.
- Проверка: файлы видны после обновления окна.
- Где связано: установка любых `.claude/skills/*`.

### 2026-08-30 — Python недоступен для skill-инструкций

- Симптом: команды вида `python3 script.py` из инструкций skills (`pptx`,
  `pdf`, `docx`) завершались с exit code 49 без полезного вывода.
- Причина: на машине не установлен настоящий Python — только
  Windows-Store-заглушка.
- Решение: заменять предполагаемые Python-шаги на Node.js-эквиваленты
  (`pptxgenjs`, `pdfkit`) и/или `LibreOffice` headless CLI
  (`C:\Program Files\LibreOffice\program\soffice.exe`) для конвертаций.
- Проверка: `node --version` работает; `python3 --version` — нет (ожидаемо).
- Где связано: `project-memory.md` → факт "На машине нет Python".

### 2026-08-28 — «САМОКАТ» в банковской выписке — это не транспорт

- Симптом: при первой автокатегоризации транзакций сумма по категории
  «Транспорт и топливо» не совпала с эталонным отчётом на 7 976 ₽.
- Причина: транзакции «САМОКАТ» были отнесены к транспорту (по названию —
  логично), но на самом деле это сервис доставки продуктов, а не аренда
  самокатов.
- Решение: при категоризации банковских транзакций не полагаться только на
  название мерчанта — проверять итоговые суммы по категориям против
  независимого пересчёта из исходных данных.
- Проверка: сумма всех категорий равна строке «ИТОГО РАСХОДЫ» в
  `summary-3-2.csv`.
- Где связано: `demo-3-2/report-3-2.md`, `demo-3-2/bank_analysis-3-2.xlsx`.

### 2026-08-30 — Увеличил контейнер слайда, но не текст внутри — появилась новая пустота

- Симптом: при первом дизайн-аудите презентации нашли пустые зоны под
  карточками; при фиксе увеличил высоту карточек, но во втором раунде
  аудита выяснилось, что теперь пустая зона переместилась ВНУТРЬ карточки
  (текст не вырос пропорционально контейнеру).
- Причина: масштабировал контейнер, не пересчитав отступы/шрифт внутри него.
- Решение: при увеличении блока под контент — либо пропорционально увеличить
  сам контент (шрифт, интерлиньяж), либо уменьшить контейнер обратно под
  фактический объём текста, а не расширять его "на глаз".
- Проверка: рендер слайда в PNG — нет пустой зоны ни снаружи, ни внутри
  контейнера.
- Где связано: генератор `presentation-3-3.pdf` (слайд 5), второй раунд
  дизайн-аудита.

### 2026-08-30 — Неверный относительный путь при копировании файлов в новую структуру

- Симптом: в `design-elements-pack/SKILL.md` ссылка на
  `references/comparison-page-skeleton.md` вела в никуда.
- Причина: при ручном распределении 10 плоских файлов по `references/` и
  `templates/` файл реально положили в `templates/`, а в тексте SKILL.md
  написали путь по старой мысленной раскладке, не сверившись с фактическим
  расположением.
- Решение: после копирования файлов в новую структуру — всегда сверять
  каждую ссылку в документации с реальным расположением файла на диске
  (например, `grep` по всем упомянутым путям), а не полагаться на память.
- Проверка: автоматическая проверка всех `references/`/`templates/` ссылок
  во всех `SKILL.md` — использовалась при аудите навыков.
- Где связано: `.claude/skills/design-elements-pack/SKILL.md`.

### 2026-08-30 — Собственная ошибка в bash-скрипте извлечения ключей из credentials.md

- Симптом: тестовый запрос к Tavily и Firecrawl API вернул 401
  Unauthorized для обоих сервисов сразу после того, как ключи были
  подтверждённо сохранены и рабочие.
- Причина: `grep -A1 "^### Tavily"` захватывал строку `- Тип: API key`
  (следующую после заголовка), а не строку `- Значение: ...` — в
  результате в запрос отправлялся пустой ключ.
- Решение: перед тем как делать вывод о неисправности внешнего сервиса —
  сначала проверить, что скрипт извлечения данных действительно передаёт
  то, что должен (например, вывести длину извлечённой строки перед
  использованием, не сам секрет).
- Проверка: длина извлечённого ключа совпала с ожидаемой (58 и 35
  символов) перед повторным тестовым запросом — тесты прошли на 200 OK.
- Где связано: тестирование ключей `credentials.md` (Tavily/Firecrawl).

### 2026-08-30 — Путаница между `Cloud Code работа` и `CLAUDE-CODE-1`

- Симптом: пользователь несколько раз не находил файлы, когда искал их не
  в том месте.
- Причина: два похоже звучащих названия папок с разным назначением —
  `CLAUDE-CODE-1` (рабочий git-репозиторий со skills и CLAUDE.md) и
  `Cloud Code работа` (ежедневный архив готовых результатов, не
  репозиторий). Плюс само название «Cloud» вместо «Claude» — вероятная
  опечатка при голосовом вводе, которую так и не переспросили окончательно.
- Решение: явно проговаривать разницу каждый раз, когда даётся путь к
  одной из двух папок; при поиске файлов сначала уточнять, в каком именно
  месте пользователь смотрит.

- Где связано: `project-memory.md` → словарь терминов.
