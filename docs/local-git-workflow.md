# Local Git workflow

Локальный Git даёт историю изменений на этом компьютере, а GitHub
подключается отдельно для облачного бэкапа, pull requests, команды и
автоматизаций.

**С 2026-08-31 GitHub подключён** (приватный репозиторий
`damirclaude2-code/C-Users-sabir-OneDrive-CLAUDE-CODE-1`, remote `origin`).
`git push` теперь возможен, но выполняется только по явному запросу
пользователя — это правило не меняется от того, что технически стало
возможно пушить.

## Базовый цикл

- чтобы сохранить состояние проекта: `git status`, затем `git add .`, затем
  `git commit -m "Короткое описание изменений"`;
- чтобы посмотреть историю: `git log --oneline --max-count=10`;
- чтобы посмотреть изменения до commit: `git status` и `git diff`.

## Русский словарь для Claude Code

Если пользователь пишет "сохрани точку", "зафиксируй изменения", "сделай
снимок проекта", "сделай локальный commit" или "сохрани состояние перед
экспериментом", это означает:

1. Выполнить `git status`.
2. Показать список изменённых файлов.
3. Проверить, что среди файлов нет секретов, `.env`, credentials-файлов,
   приватных ключей и больших временных артефактов.
4. Если всё безопасно, выполнить `git add .` и
   `git commit -m "Короткое описание изменений"`.
5. Не выполнять `git push`, если пользователь явно не попросил подключить
   GitHub.

Если пользователь пишет "что изменилось?", "покажи изменения", "покажи
diff" или "проверь, что поменялось", это означает:

1. Выполнить `git status`.
2. Выполнить `git diff`.
3. Коротко объяснить изменения человеческим языком.

Если пользователь пишет "покажи историю", "какие были сохранения" или
"какие были commit", это означает:

1. Выполнить `git log --oneline --max-count=10`.
2. Объяснить последние сохранения человеческим языком.

Если пользователь пишет "откати последний файл", "верни файл как было" или
"отмени изменения в файле", это означает:

1. Сначала показать, какие изменения будут потеряны.
2. Не делать массовый откат всей папки.
3. Откатывать только конкретный файл.
4. Перед откатом спросить подтверждение пользователя.

## Правила безопасности

- Commit можно делать после проверки списка файлов.
- Push нельзя делать без явного запроса пользователя.
- Массовый откат всей папки нельзя делать без явного подтверждения
  пользователя.
- Секреты, токены, `.env`, credentials-файлы и приватные ключи не должны
  попадать в Git.
