# SIMPLE gateway

## Назначение

SIMPLE-дорожка — для задач, где не нужна самая сильная модель:

- классификация сообщений;
- парсинг текста;
- извлечение полей;
- короткие summary;
- JSON-ответы;
- routing внутри автоматизаций (например n8n/Activepieces);
- первичная проверка текста.

Смысл SIMPLE-дорожки — не "дешевле", а именно "без оплаты за токены" за счёт
free-tier ключей и авто-переключения между ними.

## Рекомендуемый стек

- **LiteLLM Proxy** как OpenAI-compatible proxy — снаружи один и тот же формат запроса, неважно, какой провайдер отвечает внутри;
- **Gemini Flash** как основной бесплатный provider;
- **Groq** (быстрые модели) как fallback;
- опционально **OpenRouter** free-модели как дополнительный fallback — только если понятны лимиты free-tier;
- ротация ключей;
- cooldown при ошибке 429 (превышен лимit);
- логирование без текста промптов, если в проекте есть чувствительные данные (у нас, например, финансовые/бизнес-данные VESSARI — текст промптов в лог не пишем).

## Где взять ключи

```text
Gemini: https://aistudio.google.com/apikey
Groq: https://console.groq.com/keys
OpenRouter optional: https://openrouter.ai/settings/keys
```

Подробнее про хранение ключей — в [`credentials-checklist.md`](credentials-checklist.md).

## Важно про названия моделей

Точные названия и бесплатные лимиты моделей у Gemini/Groq/OpenRouter периодически
меняются. Поэтому в документах и коде проекта используются **стабильные
внутренние alias**, а не имя конкретной модели:

- `simple-fast` — быстрый общий ответ;
- `simple-json` — структурированный JSON-ответ;
- `simple-summary` — сжатие/суммаризация текста;
- `simple-router` — классификация/маршрутизация внутри автоматизаций.

Какая конкретная модель стоит за alias — настраивается один раз внутри
gateway (см. [`litellm-config.example.yaml`](litellm-config.example.yaml)), а
не разбросано по всем местам, где gateway вызывается.
