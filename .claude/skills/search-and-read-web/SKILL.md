# Search And Read Web

Ты помогаешь Claude Code работать с актуальными данными из интернета.

## Trigger (когда использовать)

Используй этот навык, если задача зависит от:

- свежих новостей;
- актуальных цен;
- текущих правил платформ;
- описаний продуктов и сервисов;
- сайтов конкурентов;
- конкретных веб-страниц;
- сравнений, которые могут устареть.

## Главное правило

Если информация может быть устаревшей, не отвечай только из памяти.

Сначала проверь, какие источники нужны.

## Роли инструментов

- Tavily нужен для поиска и первичного набора источников.
- Firecrawl нужен для чтения и извлечения содержимого найденных страниц.

## Sequence Canon (порядок работы)

1. Определи, действительно ли задаче нужны свежие данные.
2. Если да, сформулируй, что именно нужно проверить.
3. Используй Tavily для поиска источников.
4. Используй Firecrawl для чтения ключевых страниц.
5. Собери результат так, чтобы было видно:
   - какие факты подтверждены;
   - какими ссылками они подтверждены;
   - что осталось непроверенным;
   - где ты делаешь осторожный вывод, а не утверждаешь факт.

## Формат ответа

Используй понятную структуру:

```text
Что проверял:
- ...

Какие источники нашел:
- ...

Что подтверждено:
- ...

Что пока не подтверждено:
- ...

Осторожный вывод:
- ...
```

## Если сервисы не подключены

Если ключей нет или поиск/чтение сайтов недоступны:

- честно скажи об этом;
- не имитируй поиск;
- предложи ручной запасной путь: пользователь может дать ссылку, PDF, CSV,
  текст страницы или набор источников.

## Anti-Patterns (чего не делать)

- Не делай вид, что источник прочитан, если он не был прочитан.
- Не подменяй свежие данные памятью без явной пометки.
- Не скрывай, что часть вывода остается гипотезой.
- Не смешивай проверенные факты и предположения в один список.

## Качество результата

Считай результат хорошим только если:

- каждый факт в ответе привязан к конкретному источнику (ссылке), а не
  просто заявлен;
- честно показано, что осталось непроверенным, а не сглажено молчанием;
- если ключи Tavily/Firecrawl не подключены или недоступны — это сказано
  прямо, а не имитирован результат;
- пользователь может отличить проверенный факт от осторожного вывода по
  самой структуре ответа, а не только по интонации.

## Быстрая проверка перед отдачей

- Каждый факт подтверждён ссылкой на источник?
- Не выдал ли я догадку за проверенный факт?
- Если сервис недоступен — сказал ли я об этом прямо, вместо того чтобы
  промолчать и ответить из памяти?
