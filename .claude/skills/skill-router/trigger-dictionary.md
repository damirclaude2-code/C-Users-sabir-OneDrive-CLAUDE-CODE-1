# Словарь автовыбора навыков (RU)

Этот файл — расширение к `SKILL.md` навыка `skill-router`.

## Главное правило

Автовыбор навыка должен работать **всегда**, на каждом запросе пользователя,
а не только когда пользователь явно пишет "use skills" / "примени навыки" /
"автовыбор навыков". Явная команда — это просто ещё один способ попросить о
том же самом, а не единственный способ включить логику.

Перед тем как приступать к любому нетривиальному запросу:

1. Молча сверь формулировку запроса со словарём ниже.
2. Если есть уверенное совпадение с одним навыком — применяй его сразу,
   не спрашивая разрешения на "включение навыка" (это не то же самое, что
   разрешение на само действие — план/подтверждение перед действием
   работает как обычно).
3. Если совпадений с двумя навыками — собери короткую цепочку
   (см. "Типовые маршруты" в `SKILL.md`).
4. Если совпадений нет или запрос сырой/двусмысленный — сначала
   `auto-prompt-upgrade`.
5. Называть вслух "включаю навык X" нужно только в неочевидных или составных
   случаях (см. `SKILL.md`, пункт 6 Sequence Canon) — для простых очевидных
   запросов просто используй нужный режим работы молча, не превращая ответ в
   отчёт о том, какой навык выбран.

## Словарь по навыкам

### `auto-prompt-upgrade`

Явные команды:
- "автоулучши запрос", "автоулучши промпт"
- "дострой запрос"
- "улучши промпт"
- "сделай запрос лучше"

Неявные сигналы (задача сама по себе сырая/рискованная):
- запрос короче одной фразы без цели, файлов или формата результата;
- "сделай что-нибудь с этим", "разберись", "поколдуй над этим";
- запрос сразу про крупное необратимое действие без деталей.

### `copywriter`

- "напиши", "перепиши", "составь текст";
- "лендинг", "письмо", "рассылка", "пост", "сторис";
- "оффер", "УТП", "коммерческое предложение", "КП";
- "заголовок", "заголовки", "слоган", "тайтл";
- "CTA", "призыв к действию";
- "описание товара", "описание услуги", "карточка товара";
- "сценарий для видео", "сценарий звонка";
- "сделай текст сильнее", "текст звучит слабо", "текст как нейросеть написала";
- "email", "имейл", "цепочка писем".

### `designer`

- "улучши дизайн", "поправь дизайн";
- "переделай слайд", "переделай экран", "переделай страницу";
- "визуально шумно", "перегружено", "нечитаемо";
- "плохая иерархия", "непонятно что главное";
- "улучши композицию", "поправь вёрстку", "поправь макет";
- "что здесь не так по дизайну", "аудит дизайна";
- "сделай спокойнее", "сделай профессиональнее";
- "дашборд выглядит плохо", "интерфейс неудобный".

### `design-elements-pack`

- "собери лендинг", "сделай лендинг с нуля";
- "нужна pricing страница", "страница с тарифами";
- "сравнение тарифов", "comparison страница", "страница сравнения";
- "собери слайд с нуля", "сделай презентацию с нуля";
- "какие блоки здесь нужны", "с чего начать структуру";
- "прототип страницы", "структура сайта", "структура лендинга";
- "хочу сайт", "нужен сайт", "нужна страница под продукт".

### `search-and-read-web`

- "найди", "поищи", "погугли", "загугли";
- "проверь в интернете", "посмотри в сети";
- "актуальные цены", "текущие тарифы", "что сейчас с ценами";
- "что нового", "свежие новости", "последние новости";
- "какие сейчас правила", "актуальные условия", "правила площадки";
- "сайт конкурента", "что у конкурентов", "посмотри у них на сайте";
- "что говорят источники", "проверь источники";
- "прочитай эту страницу", "открой ссылку", "зайди на сайт".

### `design-style-policy` (не отдельный skill, а правило внутри `design-elements-pack`/`designer`)

Override-сигналы — если встречаются, НЕ применяй bundled design baseline:
- "не используй design-elements-pack";
- "не используй загруженный дизайн-стиль";
- "не опирайся на shadcn/daisyUI";
- "подбери другой визуальный стиль";
- "используй мой референс вместо библиотеки";
- "сделай не как в библиотеке, а в другом направлении".

### `web-design-libraries-setup` (часть установки, не разговорный триггер)

Signals, что нужна code-level реализация (а не просто структура/дизайн):
- "поставь shadcn", "накати компоненты", "нужны реальные компоненты";
- "сделай рабочий сайт на React/Next/Vite/Astro";
- "собери прод-версию страницы", "нужен рабочий код, не просто макет".

### `fact-checking` (⚠ навык не установлен в этом проекте)

Если запрос похож на:
- "проверь цифры", "это правда?", "перепроверь факты";
- "актуальны ли эти данные", "не устарело ли это";

— а навыка нет, веди себя так: сначала попробуй `search-and-read-web` для
проверки через реальные источники, и явно скажи пользователю, что
специализированного `fact-checking` пока нет в проекте (см. `CLAUDE.md`).

## Как разрешать конфликты между навыками

- "сделай презентацию" без уточнений → сначала `design-elements-pack`
  (структура с нуля), не `designer`.
- "улучши презентацию" / "она уже есть, но..." → `designer`, не
  `design-elements-pack`.
- "напиши текст для лендинга" + "собери лендинг" в одном запросе →
  `design-elements-pack -> copywriter` (сначала структура, потом текст внутрь
  неё).
- "проверь и перепиши" → `search-and-read-web -> fact-checking -> copywriter`,
  но т.к. `fact-checking` не установлен — `search-and-read-web -> copywriter`
  с честной пометкой, что факт-чек не автоматизирован.

## Зачем этот файл существует отдельно от SKILL.md

`SKILL.md` навыка `skill-router` описывает *логику* маршрутизации.
Этот файл — *словарь конкретных русских слов и фраз*, по которым логика
срабатывает. Если в будущем найдутся новые устойчивые формулировки
пользователя, которые должны triggerить конкретный навык — дополняй именно
этот файл, не увеличивая `SKILL.md`.
