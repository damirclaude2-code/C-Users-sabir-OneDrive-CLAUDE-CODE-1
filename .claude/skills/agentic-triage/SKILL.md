# Agentic Triage

Agentic triage - это короткая первичная оценка задачи перед действием.

Твоя цель не в том, чтобы замедлять любую работу. Твоя цель - отличить маленькую
безопасную задачу от задачи, где можно сломать файлы, данные, стиль, факты,
доступы или рабочий процесс.

## Когда использовать

Используй этот skill автоматически, если задача нетривиальная.

Задача нетривиальная, если есть хотя бы один признак:

- нужно создавать, менять, переносить или удалять несколько файлов;
- запрос широкий: "разберись", "исправь", "улучши", "наведи порядок",
  "сделай все", "дотяни", "подготовь полностью";
- задача связана с ошибкой, диагностикой, багом, регрессией или непонятной
  причиной;
- нужны свежие данные, источники, цены, законы, расписания, библиотеки или
  внешние факты;
- затрагиваются деньги, доступы, API ключи, персональные данные, юридические
  тексты, безопасность или публикация;
- нужно устанавливать зависимости, менять настройки, запускать миграции,
  деплоить, пушить, отправлять сообщения или делать другой side effect;
- задача меняет LLM/agent/prompt/skill/router/MCP/workflow поведение;
- есть риск испортить дизайн, презентацию, код, структуру папки или чужую
  работу.

Не используй длинный triage для совсем маленьких безопасных задач:

- прочитать файл и кратко ответить;
- показать список файлов без изменений;
- поправить одну очевидную опечатку;
- ответить на простой вопрос без свежих данных и без изменения проекта.

## Trigger

Включай `agentic-triage`, если пользователь прямо пишет:

- "сначала оцени задачу";
- "проверь задачу перед действием";
- "сделай agentic triage";
- "сделай триаж задачи";
- "оцени риск";
- "перед изменениями оцени риск";
- "безопасно сделай";
- "не ломай, сначала проверь";
- "сначала план";
- "разберись и исправь";
- "наведи порядок";
- "улучши, но не сломай";
- "proof loop";
- "use skills".

Также включай skill без явной команды, если сама задача нетривиальная по
признакам выше.

## Что этот навык чинит

- агент слишком быстро начинает править файлы;
- агент удаляет или переносит что-то без рамки;
- агент отвечает из памяти там, где нужны свежие источники;
- агент лечит симптом вместо причины;
- агент выбирает skills, не поняв риск задачи;
- агент говорит "готово" без понятного proof gate;
- агент делает prompt-only fix там, где нужны правила, тесты или проверка.

## Sequence Canon

1. Определи, задача trivial или non_trivial.

   `trivial` разрешен только если задача маленькая, безопасная, обратимая, не
   требует свежих данных, не меняет agent/workflow/prompt behavior и не имеет
   side effects.

   Если сомневаешься, считай задачу `non_trivial`.

2. Назови task class.

   Используй простую классификацию:

   - `not_agentic` - задача сложная, но не про agent/LLM/workflow/prompt;
   - `llm_boundary` - меняется поведение модели, промпта, генерации, judge или
     parser;
   - `agent_workflow` - меняется skill, router, MCP/tool workflow, автономная
     работа агента или installer;
   - `side_effecting_workflow` - есть отправки, удаления, деплой, API mutation,
     платежи, credentials, внешние системы;
   - `runtime_infra` - инфраструктура, сервисы, worker, cron, gateway, prod;
   - `eval_only` - только оценка, benchmark, golden, проверка качества.

3. Выбери protocol path.

   - `skip_written_triage` - только для маленьких read-only или одношаговых
     безопасных задач;
   - `skip_full_gate` - задача нетривиальная, но не меняет agent/LLM/workflow
     surface;
   - `full_architecture_gate` - задача меняет agent, LLM, prompt, skill,
     router, MCP, tool-calling, workflow, side-effecting automation или чинит
     повторяющийся LLM-баг.

4. Коротко оцени риск.

   Используй три уровня:

   - `low` - можно продолжать после короткой рамки;
   - `medium` - сначала план, чтение контекста, proof после изменений;
   - `high` - сначала уточнение, backup, явное подтверждение или proof loop.

5. Определи безопасный следующий шаг.

   Примеры:

   - сначала прочитать файлы;
   - сначала найти источник;
   - сначала сделать план;
   - сначала проверить текущую структуру;
   - сначала спросить подтверждение;
   - сначала предложить rollback/proof strategy.

6. После triage передай задачу дальше.

   Если нужен skill-router, подключи его после triage. Triage отвечает на
   вопрос "можно ли и как безопасно действовать?", а skill-router отвечает на
   вопрос "какой навык нужен?".

## Короткий формат вывода

По умолчанию пиши очень коротко:

```text
Task class: <...>
Reason: <одна конкретная причина>
Protocol path: <...>
Risk: <low|medium|high>
Safe next step: <...>
```

Если пользователь не просил подробный разбор, не раздувай triage.

Для совсем простых задач можно не показывать весь блок и сразу помочь.

## Anti-patterns

- Не превращай каждую мелочь в длинную церемонию.
- Не называй риск "низким", если есть удаление, деплой, секреты, деньги,
  внешняя отправка или массовые правки.
- Не начинай правки до чтения контекста, если задача зависит от существующих
  файлов.
- Не спрашивай пользователя то, что можно безопасно выяснить самому.
- Не выбирай skills до понимания риска.
- Не делай prompt-only fix для повторяющегося LLM/agent бага без proof или
  golden case.
- Не заявляй "готово" без проверки результата, если был side effect.

## Quality Gate

Хороший результат:

- маленькие задачи не перегружены формальностью;
- нетривиальные задачи получают короткий triage до действия;
- уровень риска объяснен конкретной причиной;
- следующий шаг безопасен и обратим, если это возможно;
- high-risk действия не выполняются молча;
- triage не заменяет работу, а помогает выбрать правильный маршрут.

## Self-check

Перед финалом проверь:

- не сделал ли я triage слишком длинным для простой задачи;
- не пропустил ли side effect;
- не надо ли было сначала прочитать файл или источник;
- есть ли proof gate для результата.
