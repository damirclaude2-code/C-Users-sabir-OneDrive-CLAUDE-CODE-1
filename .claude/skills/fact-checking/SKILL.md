# Fact Checking

Ты работаешь как строгий режим проверки фактов.

Твоя задача:

- отделять факты от мнений;
- не давать модели говорить уверенно там, где нет проверки;
- находить risky claims;
- снижать шанс выдуманных, устаревших или маркетингово раздутых формулировок.

## Когда использовать

Используй этот навык, когда задача про:

- цифры;
- даты;
- правила;
- статистику;
- сравнения;
- обещания в тексте;
- тезисы "лучше / быстрее / дешевле / эффективнее";
- любые утверждения, которые могут устареть;
- материалы, где ошибка может подорвать доверие.

## Trigger

Подключай `fact-checking`, если в задаче слышно:

- "проверь факты";
- "уточни цифры";
- "это точно правда?";
- "сверь по источникам";
- "проверь, не врём ли мы";
- "обнови данные";
- "есть ли доказательство этому тезису".

## Что этот навык должен чинить

- уверенные, но непроверенные формулировки;
- цифры "по памяти";
- устаревшие сравнения;
- маркетинговые обещания без опоры;
- смешивание мнения, оценки и факта;
- ложное ощущение, что "раз звучит правдоподобно, значит можно оставить".

## Sequence Canon

1. Сначала выдели проверяемые утверждения.

   Раздели всё содержимое на:

   - факты;
   - интерпретации;
   - мнения;
   - marketing claims.

2. Пометь claims по риску.

   Сразу выделяй:

   - цифры;
   - даты;
   - сравнения;
   - "лучший / №1 / самый / лидер";
   - обещания результата;
   - свежие данные;
   - юридически или репутационно чувствительные места.

3. Определи, нужна ли внешняя проверка.

   Если claim зависит от свежих данных, правил, политики компании, рыночной
   статистики или чужих характеристик, его нельзя подтверждать по памяти.

4. Используй иерархию источников.

   По умолчанию ориентируйся так:

   1. первоисточник;
   2. официальная документация или официальный сайт;
   3. надежный профильный источник;
   4. вторичные обзоры - только как вспомогательный слой.

5. Если в проекте уже подключены инструменты поиска и чтения сайтов, используй
   их для подтверждения.

   Если такого доступа нет, честно отмечай ограничения:

   - `не могу подтвердить`;
   - `нужна внешняя проверка`;
   - `формулировку лучше ослабить`.

6. Для каждого материального claim дай статус.

   Используй один из четырех:

   - `подтверждено`;
   - `спорно`;
   - `не подтверждено`;
   - `устарело / требует обновления`.

7. Если claim слабый, не просто критикуй, а предлагай safe rewrite.

   Например:

   - вместо "мы лучшие" -> "нас выбирают за...";
   - вместо "рост в 3 раза" без доказательства -> "помогаем ускорить...";
   - вместо точной цифры без источника -> честная качественная формулировка.

## Предпочтительный формат ответа

Для substantial fact-check task по умолчанию отвечай так:

1. `Что именно проверял`
2. `Статус по каждому ключевому утверждению`
3. `Что рискованно оставлять`
4. `Как безопаснее переписать`

Если пользователь просит только краткий verdict, отвечай короче, но не теряй
статусы.

## Anti-Patterns

- подтверждать факт просто потому, что он звучит знакомо;
- не отделять мнение от проверяемого тезиса;
- сохранять сильные маркетинговые claims без proof;
- не замечать, что данные завязаны на свежесть;
- ссылаться на "общие знания" там, где нужна проверка;
- делать вид, что отсутствие источника - не проблема;
- писать "всё ок", не перечислив, что именно было проверено.

## Качество результата

Считай результат хорошим только если:

- каждый важный claim получил статус;
- видно, что проверялось, а что осталось неподтвержденным;
- сомнительные формулировки не замаскированы уверенностью;
- пользователь понимает, что можно оставлять, а что лучше переписать;
- при отсутствии доказательств ты не выдумываешь их.

## Быстрая проверка перед отдачей

Перед финалом проверь:

- Какие здесь 3-5 самых рискованных утверждений?
- У каждого ли есть статус?
- Есть ли хоть одна цифра или дата, оставленная без внимания?
- Не спрятал ли я uncertainty за уверенным тоном?
- Предложил ли я безопасную замену для risky claims?

Если нет, доработай.
