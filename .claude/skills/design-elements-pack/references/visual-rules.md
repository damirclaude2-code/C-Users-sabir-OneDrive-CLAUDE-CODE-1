# Visual Rules

Это визуальный baseline pack-а.

Он собран из локальных HWAI design rules и нужен, чтобы Claude Code не
скатывался в generic AI aesthetics.

## Главный принцип

Сначала структура, потом красота.

Если порядок блоков плохой, лишний цвет и лишние карточки не спасут результат.

## Что считать хорошим visual direction

- главный смысл виден первым;
- блоки идут в понятном ритме;
- акценты дозированы;
- текст не распирает контейнеры;
- экран не выглядит случайным;
- интерфейс или слайд выглядит собранно, а не декоративно.

## Что избегать

- слишком много карточек подряд;
- одинаковая визуальная сила у всех элементов;
- фиолетово-синие generic gradients;
- тесные блоки без воздуха;
- крупные hero-типы внутри мелких служебных панелей;
- бесконтрольные rounded rectangles;
- украшательство до решения hierarchy problem.

## Для бизнесовых экранов и слайдов

По умолчанию предпочитай:

- спокойную подачу;
- плотный, но чистый layout;
- restrained color story;
- predictable scan path;
- utility-first hierarchy.

Не делай:

- маркетинговый "космос";
- bento-card chaos;
- декоративные floating sections без смысла.

## Для CTA и proof-блоков

- CTA должен быть один главный;
- proof должен стоять рядом с сильными claims;
- proof strip не должен забирать внимание у hero.

## Для pricing и comparison

- помогай self-selection;
- различия должны считываться за секунды;
- vague labels вроде "advanced features" ослабляют блок.

## Быстрый visual self-check

- Что здесь видно первым?
- Где слишком много акцентов?
- Что можно убрать?
- Видно ли разницу между headline, body и caption?
- Не выглядит ли это как стандартный AI-лендинг без характера?
